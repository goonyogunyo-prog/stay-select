GitHub-onlyファイルの安全な復元

このページと付属スクリプトはGitHubへ書き込みません。GitHub mainにしかないファイルを累積ZIPへ追記し、同名で内容が異なるファイルは旧ZIPのバイトを守って競合として報告します。mainへのZIP一括上書きは禁止です。

使い方

  1. GitHub main HEADを再確認し、作業開始・終了で同一であることを確認する。
  2. そのHEADに固定したrecursive tree JSONとGitHubコミットZIPを取得する。HEADが変わった場合は両方を新HEADで取り直す。
  3. 累積ZIPと旧manifestを用意し、オフライン復元スクリプトをPython 3で実行する。
  4. CSVのGitHub-only、同名競合、ZIP-onlyをレビューする。競合がある場合、既定では新ZIPを出力せず停止する。
  5. 競合を旧ZIP側で保全する必要がある場合のみ、明示フラグを付けて新ZIPを作成。出力できても公開承認ではない。
python tools/merge_github_only_safe.py \
  --local cumulative.zip \
  --github-zip github-pinned.zip \
  --tree github-tree.json \
  --head 88979175bd151bdba6949c517f0e50c653eb053e \
  --manifest old-manifest.txt \
  --output merged-review.zip \
  --report github-recovery-report.csv \
  --status github-recovery-status.json

競合を保全したまま出力する場合に限り、末尾に --preserve-local-conflicts を付けます。GitHub側の1,258 blobはアーカイブ内の実バイトとGit blob SHAで全件照合します。取得漏れ、SHA不一致、危険なパス、旧manifest不一致は停止します。
